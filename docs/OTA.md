# التحديث الهوائي (OTA) — تطبيق HDR

## الفكرة

إصلاحات كود JavaScript والتصميم والنصوص تصل للأجهزة **في دقائق** دون بناء APK جديد.

- **APK جديد** → فقط عند: تغيير كود native، إضافة مكتبة native، صور محلية جديدة، تغيير AndroidManifest.
- **تحديث هوائي** → كل ما عداه: منطق، شاشات، ألوان، نصوص، إصلاحات أخطاء JS.

## كيف يعمل

```
┌─────────────┐     ┌──────────────┐     ┌──────────────┐
│ التطبيق     │     │ manifest.json│     │ حزمة Hermes  │
│ عند الإقلاع │────▶│ (Firebase    │────▶│ (.hbc)       │
│ يفحص النسخة │     │  Storage)    │     │              │
└─────────────┘     └──────────────┘     └──────────────┘
       │                                            │
       │  تحميل + حفظ في filesDir/ota/              │
       │◀───────────────────────────────────────────┘
       │
       │  إعادة تشغيل → الكود الأصلي يتحقق (SHA256 + حداثة)
       │  ويحمّل الحزمة الجديدة بدل المدمجة
       ▼
```

### الأمان
1. **HTTPS فقط** — التحميل من Firebase Storage عبر HTTPS.
2. **تحقق SHA256** — الكود الأصلي (`OtaBundle.kt`) يتحقق من بصمة الحزمة قبل كل إقلاع؛ أي عبث = حذف الحزمة والرجوع للمدمجة.
3. **حماية من القدم** — إن حُدّث الـAPK بعد تحميل الحزمة، تُتجاهل الحزمة تلقائيًا.

### الأوفلاين
الفحص "أفضل جهد" بمهلة 8 ثوانٍ ولا يمنع الإقلاع أبدًا. بدون إنترنت يعمل التطبيق طبيعيًا بالحزمة المدمجة أو آخر تحديث محمّل.

## الإعداد لمرة واحدة

### 1. تفعيل Firebase Storage
1. افتح [Firebase Console](https://console.firebase.google.com) ← مشروع `souq-alsharq-app`
2. Build ← Storage ← "Get started" (الخطة المجانية Spark كافية)
3. القواعد الحالية (`storage.rules`) تسمح بالقراءة العامة لمسار `admin/**` — لا تغيير needed.

### 2. التأكد من دمج الكود
كود OTA مدمج في الفرع `ota`. عند دمجه في `main` وبناء APK جديد، يصبح التحديث الهوائي فعالًا.

## دفع تحديث جديد

```bash
cd ~/workspace/sharq-catalog/SharqApp
./scripts/ota/push-ota-update.sh 1.0.1 "إصلاح عرض الأسعار في البطاقات"
```

السكربت يقوم تلقائيًا بـ:
1. بناء حزمة JS من الكود الحالي
2. ترجمتها إلى Hermes bytecode (مطابق للـAPK)
3. حساب SHA256
4. رفعها إلى `admin/ota/hdr/` في Firebase Storage
5. تحديث `manifest.json` (بدون تخزين مؤقت)

خلال دقائق من فتح التطبيق، يظهر إشعار التحديث في شاشة الحساب.

### رفع رقم الـruntime
إن غيّرت كودًا أصليًا (native) في إصدار APK جديد، ارفع `OTA_RUNTIME` في `src/ota/otaConfig.ts`
(مثلًا من `'1'` إلى `'2'`) حتى لا تُدفع حزم قديمة لأجهزة جديدة.

### التراجع عن تحديث
- **سريع:** أعد تشغيل السكربت بنسخة أقدم (مثلًا `1.0.0`) — الأجهزة ستعود لها.
- **فوري:** احذف `manifest.json` من Storage — الأجهزة تتوقف عن رؤية التحديث.
- **من الجهاز:** شاشة الحساب ← تحديثات التطبيق ← (بعد التحميل) يمكن تجاهل التحديث.

## ما لا يدعمه التحديث الهوائي

| الحالة | الحل |
|---|---|
| مكتبة native جديدة | بناء APK جديد |
| صور محلية جديدة (`require`) | بناء APK جديد |
| تغيير AndroidManifest / أذونات | بناء APK جديد |
| تغيير رقم `OTA_RUNTIME` | بناء APK جديد |

## البنية التقنية

| الملف | الدور |
|---|---|
| `android/.../OtaBundle.kt` | فحص الحزمة عند الإقلاع (وجود + حداثة + SHA256) |
| `android/.../MainApplication.kt` | تمرير `jsBundleFilePath` لـ ReactHost |
| `src/ota/otaConfig.ts` | الثوابت والأنواع |
| `src/ota/UpdateManager.ts` | الفحص/التحميل/التطبيق |
| `src/ota/OtaContext.tsx` | حالة React المشتركة |
| `src/ota/OtaSection.tsx` | واجهة شاشة الحساب |
| `scripts/ota/push-ota-update.sh` | سكربت الدفع |

## للمطورين: اختبار محلي

```bash
# 1) بناء حزمة تجريبية
npx react-native bundle --platform android --dev false \
  --entry-file index.js --bundle-output /tmp/test.bundle

# 2) ترجمة Hermes
./node_modules/hermes-compiler/hermesc/linux64-bin/hermesc \
  -emit-binary -out /tmp/test.hbc /tmp/test.bundle

# 3) فحص النوع
npx tsc --noEmit

# 4) اختبارات الوحدة
npx jest __tests__/ota.test.ts
```

> **ملاحظة:** الاختبار الحقيقي على جهاز يتطلب APK مبنيًا من فرع `ota`.
